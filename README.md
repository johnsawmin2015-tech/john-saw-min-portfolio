# John Saw Min — Portfolio

A server-rendered engineering portfolio built with React, TypeScript, TanStack Start, and Tailwind CSS. Project case studies are modeled as typed content, while the interactive surface stays intentionally small: navigation, responsive menus, and project filtering.

## Requirements

- Node.js 22.12–24
- npm 11

## Local development

```sh
npm ci
cp .env.example .env.local
npm run dev
```

The values in `.env.local` are public portfolio configuration, not secrets. Links are hidden when their variables are missing or invalid, so a clean checkout never publishes placeholder contact details or a broken résumé.

| Variable             | Purpose                                                                             |
| -------------------- | ----------------------------------------------------------------------------------- |
| `VITE_SITE_URL`      | Production origin used for canonical, Open Graph, structured-data, and sitemap URLs |
| `VITE_CONTACT_EMAIL` | Public contact address                                                              |
| `VITE_GITHUB_URL`    | Full GitHub profile URL                                                             |
| `VITE_LINKEDIN_URL`  | Full LinkedIn profile URL                                                           |
| `VITE_RESUME_URL`    | Root-relative or HTTPS résumé URL                                                   |

If `VITE_RESUME_URL=/resume.pdf`, place the real document at `public/resume.pdf` before deployment.

## Quality gate

```sh
npm run check
```

The check runs formatting verification, strict TypeScript, ESLint, unit tests, and the production build. The same command runs on every push and pull request in GitHub Actions.

Individual commands:

```sh
npm run format
npm run typecheck
npm run lint
npm test
npm run build
```

## Production preview and deployment

The production target is a Cloudflare Worker generated by Nitro.

```sh
npm run preview
```

This creates a fresh `.output` build and serves it with the pinned Wrangler dependency. After signing in to the intended Cloudflare account and confirming the generated worker configuration:

```sh
npm run deploy
```

Deployment is an external side effect; inspect `.output/server/wrangler.json` and verify the target account and worker name before running it.

## Architecture

- `src/content` — typed portfolio and case-study content
- `src/routes` — TanStack file routes and route-level metadata
- `src/features` — interactive project presentation and filtering
- `src/components` — layout, navigation, project visuals, and reusable actions
- `src/config/public.ts` — validated public environment configuration
- `src/lib` — tested domain examples, error handling, and response security headers
- `src/server.ts` — Cloudflare/Nitro SSR entry and catastrophic-error normalization

There is no authentication, database, user-submitted data, or application API. The only server route outside page rendering is the XML sitemap.

## Content checklist before launch

1. Set every public environment value.
2. Add `public/resume.pdf` or configure an external résumé URL.
3. Add real repository/demo links and screenshots to completed project case studies.
4. Verify the Open Graph image and metadata against the production domain.
5. Run `npm run check` and `npm run preview`.
